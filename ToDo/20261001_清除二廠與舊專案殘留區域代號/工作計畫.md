## 單一任務完成 4 道 Gate

每個子任務完成、標記 `[x]` 之前必須全部通過：

| Gate | 檢查項 | 判定 |
|------|--------|------|
| 1. Build | 對應專案建置 | 0 error（warning 允許） |
| 2. Test | TDD: 對應測試 / 一般: 回歸測試 | 全部通過 |

任一 Gate 失敗 → 標 `[!] 阻塞中` + 停下找使用者，不得跳過。

## Commit 策略

- 格式比照現行 repo：`test(scp): ...`、`test(dispatch): ...`、`refactor(scp): ...`、`refactor(dispatch): ...`、`feat(scp): ...`、`feat(dispatch): ...`、`fix(scp): ...`、`docs(todo): ...`
- **每個 commit 單一目的**：純刪除（`refactor`）不可混入行為變更（`feat`）；行為變更 B1～B8 各自對應的 commit 需在訊息中標註編號
- P1 的刪除依檔案分批，一個任務一個 commit；T7 因對應 B4 另用 `feat(dispatch):`
- 版本號不在本計畫變更；現場部署前另跑 `/deployment-checklist`
