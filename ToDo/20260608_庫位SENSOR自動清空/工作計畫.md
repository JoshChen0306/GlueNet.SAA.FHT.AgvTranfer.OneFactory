# 工作計畫：庫位 SENSOR 自動清空工單與庫位狀態

- 主題：客戶在庫位安裝 SENSOR（平板偵測），經三菱 PLC M 暫存器，bit=OFF 且軟體仍佔用連續 N 輪自動清空工單與庫位狀態
- 目標專案：ACC `HikAGVWebAPI`（.NET Framework 4.8）
- 規格文件：見同資料夾 `spec.md` / `plan.md`
- 分析力度：標準模式

## 執行順序

P1（核心）：Task 1 → Task 2 → Task 3 → Task 4
P2（整合與驗證）：Task 5 → Task 6

> Task 2（掃描核心邏輯）與 Task 3（PlcDevice COM）彼此獨立，可並行；但兩者都需 Task 1 的設定類別與 Task 2 定義的 `IBitReader` 介面，故先完成 Task 1、Task 2 的介面定義後再並行 Task 3。

## 🧪 Task 2 測試案例矩陣（實作版，全部完成）

**IsOccupied 三欄位守門**

| # | 案例 | 輸入 | 預期 |
|---|------|------|------|
| 1 | RackId 非空 | RackId="R001" | true |
| 2 | WorkOrder 非空 | WorkOrder="WO123" | true |
| 3 | HaveFlag=1（有料無工單）| HaveFlag="1" | true |
| 4 | HaveFlag=3（有料有工單）| HaveFlag="3" | true |
| 5 | 三者皆空 HaveFlag=0 | 全空 | false |
| 6 | HaveFlag=E | HaveFlag="E" | false |
| 7 | port=null | null | false |

**ScanOnce 掃描與去抖**

| # | 案例 | 輸入摘要 | 預期 |
|---|------|---------|------|
| 8 | bit=ON 不清 | on, 佔用 | 計數 0、不清 |
| 9 | OFF 但軟體已空 | off, 未佔用 | 計數 0、不清 |
| 10 | 讀取失敗計數歸零 | off→fail→off→off (N=2) | fail 歸零、重累積至 2 才清一次 |
| 11 | ConfirmCount=1 當輪即清 | off, 佔用 | 清一次 |
| 12 | ConfirmCount=3 第三輪才清 | off, 佔用 ×3 | 前兩輪不清、第三輪清一次 |
| 13 | 去抖中途 ON 重置 | off,off,ON,off,off,off (N=3) | ON 後重算，第三輪才清 |
| 14 | 重啟殘留補清 | 開機即 off+佔用 ×3 | 第三輪補清一次 |
| 15 | 清空後變空不重清 | 清後 port 變空 | 不再清 |
| 16 | 多庫位獨立 | M10 off+佔用、M11 on | 只清 B1 |
| 17 | ConfirmCount≤0 防呆 | N=0, off, 佔用 | 視為 1，當輪清 |

**SensorMap 解析**：單筆 / 多筆 / 含空白與錯誤片段 / 空字串(null) 共 4 條。
