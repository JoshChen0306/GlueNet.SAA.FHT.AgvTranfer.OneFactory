## 執行順序

1. P0 子任務（前置查證 + 後端核心連動）全部完成 → 跨優先序驗證 → 進入 P1
2. P1 子任務（前端對齊 + 端對端驗證）

## 單一任務完成 4 道 Gate

每個子任務完成、標記 `[x]` 之前必須全部通過：

| Gate | 檢查項 | 判定 |
|------|--------|------|
| 1. Build | 對應專案建置 | 0 error（warning 允許） |
| 2. Test | TDD: 對應測試 / 一般: 回歸測試 | 全部通過 |
| 3. Acceptance | 逐項核對 spec.md 對應驗收標準 | 全部滿足 |
| 4. Regression | 若屬重構 / 效能優化 | 完整測試套件 0 失敗 |

任一 Gate 失敗 → 標 `[!] 阻塞中` + 停下找使用者，不得跳過。

> 本任務無 SCP 單元測試專案（決議不建），Gate 2「Test」以「與二廠逐行 diff 邏輯比對 + 端對端手動驗證」替代，並於報告註明。

## Commit 策略

- 每個 P0/P1 子任務獨立 commit，message 格式：`fix(scp): <子任務重點>`
- 純移植對齊的 commit 與行為調整分開（本案皆為對齊二廠，標註「對齊二廠」於 message）
- 範例：
  - `fix(scp): oMission entity 補 ParentTaskDateTime 對齊二廠`
  - `fix(scp): DeleteoNeed 改 taskDateTime 連動取消預調度對齊二廠`
  - `fix(scp): 派送清單前端對齊二廠（data-taskdatetime + TaskType 欄）`
